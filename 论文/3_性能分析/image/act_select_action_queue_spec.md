# 图 1：`select_action` / 动作队列逻辑

这张图只讲一件事：在线控制每一轮都只需要拿到 **1 帧动作** 去执行。

ACT 不是每一帧都重新推理。它有一个动作队列 `_action_queue`：

- 如果队列里还有动作，就直接 `popleft()` 取 1 帧出来执行。
- 如果队列空了，ACT 才完整推理一次，生成一个 action chunk。
- 当前默认 `chunk_size = 100`，也就是一次推理输出 100 帧动作。
- 这个 100 是训练配置里确定的，和模型结构/权重强相关，不是在线阶段随便改的运行参数。

## 推荐画法

画成一个很简单的分支图：

```text
需要 1 帧动作
    |
检查 _action_queue
    |
    |-- 队列非空 --> popleft 取 1 帧 --> postprocessor --> 返回动作
    |
    |-- 队列为空 --> ACT 推理 1 个 action chunk(100帧)
                    --> 写入队列
                    --> popleft 取第 0 帧
                    --> postprocessor
                    --> 返回动作
```

## 图里要强调

- `select_action` 的目标不是“一直推理”，而是“拿到当前要执行的 1 帧动作”。
- 队列非空是快速路径。
- 队列为空才触发完整 ACT 推理。
- 一次推理生成 100 帧动作，当前帧先用掉，后面的帧留在队列里。
