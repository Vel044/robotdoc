BCM2712 SoC (Raspberry Pi 5)

Relevant source files
  • arch/arm64/boot/dts/broadcom/bcm2712-ds.dtsi
  • arch/arm64/boot/dts/broadcom/bcm2712-rpi-5-b.dts

This page documents the BCM2712 System-on-Chip (SoC) used in the Raspberry Pi 5 and Compute Module 5. It covers the architecture, core components, peripheral interfaces, and device tree configuration. For information about the previous generation BCM2711 SoC used in Raspberry Pi 4, see BCM2711 SoC (Raspberry Pi 4).

Overview

The BCM2712 is Broadcom's SoC designed specifically for the Raspberry Pi 5. It represents a significant architectural evolution from the BCM2711, featuring more powerful CPU cores, enhanced graphics capabilities, and a separate RP1 I/O controller chip that handles many peripheral functions.

Key Features

  • Quad-core ARM Cortex-A76 CPU cluster
  • VideoCore VII GPU
  • Advanced power management system
  • Thermal monitoring and management
  • Dedicated RP1 I/O controller connected via PCIe

Sources: arch/arm64/boot/dts/broadcom/bcm2712-rpi-5-b.dts14-15 arch/arm64/boot/dts/broadcom/bcm2712-ds.dtsi26-33

Architecture

CPU Subsystem

The BCM2712 features four ARM Cortex-A76 cores, a significant upgrade from the Cortex-A72 cores used in the BCM2711. The SoC includes integrated performance monitoring capabilities through the ARM PMU (Performance Monitoring Unit).

Sources: arch/arm64/boot/dts/broadcom/bcm2712-ds.dtsi26-33 arch/arm64/boot/dts/broadcom/bcm2712-ds.dtsi137-143 arch/arm64/boot/dts/broadcom/bcm2712-ds.dtsi426-429

Memory System

The BCM2712 supports up to 8GB of RAM. The bootloader is responsible for setting up the memory configuration in the device tree. The SoC includes a CMA (Contiguous Memory Allocator) area of 64MB reserved for hardware that requires physically contiguous memory.

Sources: arch/arm64/boot/dts/broadcom/bcm2712-rpi-5-b.dts18-25 arch/arm64/boot/dts/broadcom/bcm2712-ds.dtsi10-23

System Layout

The BCM2712 architecture separates core processing functions from I/O operations. While the main BCM2712 chip handles CPU, GPU, and memory operations, many I/O functions are delegated to the RP1 controller connected via PCIe. This design enhances performance and allows for better thermal management.

Sources: arch/arm64/boot/dts/broadcom/bcm2712-rpi-5-b.dts122-127 arch/arm64/boot/dts/broadcom/bcm2712-rpi-5-b.dts132-161 arch/arm64/boot/dts/broadcom/bcm2712-ds.dtsi282-398

PCIe-Based RP1 Integration

A key architectural feature of the BCM2712 is how it interacts with the RP1 I/O controller via PCIe. The RP1 controller handles many peripheral functions, offloading these tasks from the main SoC and improving overall system performance.

PCIe Address Space Layout

The BCM2712 and RP1 use a carefully mapped PCIe address space to enable seamless communication:

- 00_00000000-00_00xxxxxx = RP1 peripherals
- 10_00000000-1x_xxxxxxxx = System RAM (up to 64GB)

Various DMA mappings are defined to allow the RP1 to efficiently access system memory and its own peripheral space:

  1. Outbound mapping from BCM2712 to RP1 peripheral space:

    • PCIe 0_00xxxxxx → RP1 c0_40xxxxxx

  2. Inbound mappings to allow RP1 DMA operations:

    • RP1 1x_xxxxxxxx → PCIe 1x_xxxxxxxx (System RAM)
    • RP1 c0_40xxxxxx → PCIe 00_00xxxxxx (RP1 peripheral access)
    • RP1 0x_xxxxxxxx → PCIe 1x_xxxxxxxx (Alternative RAM access)

This complex mapping scheme enables efficient data transfers between the BCM2712 and RP1 while maintaining proper memory isolation.

Sources: arch/arm64/boot/dts/broadcom/bcm2712-rpi-5-b.dts122-161

I/O and Peripherals

GPIO System

The BCM2712 features multiple GPIO controllers:

  1. Main GPIO controller (gio) with 54 pins (32 + 22 bank configuration)
  2. Always-on GPIO controller (gio_aon) for low-power operation
  3. RP1 GPIO controller for peripheral connections

These GPIO controllers are used for various functions including LED control, power button handling, storage card detection, and peripheral enabling.

Sources: arch/arm64/boot/dts/broadcom/bcm2712-ds.dtsi191-202 arch/arm64/boot/dts/broadcom/bcm2712-rpi-5-b.dts548-621

Communication Interfaces

The BCM2712 supports multiple communication interfaces:

  1. UART interfaces for serial communication (including Bluetooth)
  2. I2C controllers for device communication
  3. SPI controllers for high-speed peripheral communication
  4. SD/MMC controllers for storage devices
  5. USB controllers via the RP1

These interfaces can be configured through pinmux settings in the device tree.

Sources: arch/arm64/boot/dts/broadcom/bcm2712-rpi-5-b.dts184-186 arch/arm64/boot/dts/broadcom/bcm2712-rpi-5-b.dts364-378

Display and Camera Interfaces

The BCM2712 supports various display and camera interfaces through the RP1 controller:

  1. CSI (Camera Serial Interface) for camera input
  2. DSI (Display Serial Interface) for display output
  3. DPI (Display Parallel Interface) for parallel display connections
  4. HDMI output via dedicated controllers

Sources: arch/arm64/boot/dts/broadcom/bcm2712-rpi-5-b.dts222-237 arch/arm64/boot/dts/broadcom/bcm2712-rpi-5-b.dts271-308

Memory Management

IOMMU System

The BCM2712 features a sophisticated IOMMU (Input-Output Memory Management Unit) system to manage DMA operations safely. The SoC contains multiple IOMMU controllers for different subsystems:

  1. IOMMU2 for PISP-BE, HEVC, and H264 accelerators
  2. IOMMU4 for HVS, MPL/TXP, and other display components
  3. IOMMU5 for PCIe2 (RP1) and other components

These IOMMUs share a common cache (IOMMUC) for translation entries, improving performance.

Power and Thermal Management

Power Management Controller

The BCM2712 features a comprehensive power management system that controls power domains and reset signals. This allows selective powering and resetting of SoC components, improving energy efficiency.

Sources: arch/arm64/boot/dts/broadcom/bcm2712-ds.dtsi122-129

Thermal Monitoring

The SoC includes a built-in thermal monitoring system that measures core temperature. This is connected to a thermal management framework that can trigger cooling responses when temperature thresholds are exceeded.

The thermal management system includes multiple temperature thresholds:

Multimedia Capabilities

Video Decode/Encode

The BCM2712 includes dedicated hardware for video processing:

  1. HEVC decoder for efficient video decoding
  2. V3D GPU for 3D graphics processing
  3. VideoCore VII display pipeline components

These components share a common interrupt and clock management framework and can be individually power-controlled.

Sources: arch/arm64/boot/dts/broadcom/bcm2712-ds.dtsi371-423

Graphics Processing

The BCM2712 features an enhanced graphics processing system:

  1. VideoCore VII GPU
  2. V3D graphics processor
  3. Hardware Video Scaler (HVS)
  4. Display controllers for various outputs

The graphics system is connected to the main memory controller via the IOMMU system, enabling efficient memory allocation and protection.

Sources: arch/arm64/boot/dts/broadcom/bcm2712-ds.dtsi409-423

Device Tree Structure

The BCM2712 is described in the Linux kernel using a hierarchy of device tree files:

  1. Base SoC description: bcm2712.dtsi
  2. SoC configuration: bcm2712-ds.dtsi
  3. Raspberry Pi common elements: bcm2712-rpi.dtsi
  4. RP1 controller description: rp1.dtsi
  5. Board-specific configurations:
    • bcm2712-rpi-5-b.dts for Raspberry Pi 5 Model B
    • bcm2712-rpi-cm5.dtsi for Compute Module 5

This modular approach allows for efficient code reuse and clear separation of hardware components.

Differences from BCM2711 (Raspberry Pi 4)

The BCM2712 represents a significant architectural evolution from the BCM2711 used in Raspberry Pi 4:

FeatureBCM2711 (Pi 4)BCM2712 (Pi 5)
CPU Cores4x Cortex-A724x Cortex-A76
GPUVideoCore VIVideoCore VII
I/O ArchitectureIntegratedSeparate RP1 controller
PCIeLimitedEnhanced with multiple controllers
Memory SpeedLowerSignificantly faster
Thermal ManagementBasicAdvanced with fan control
Video DecodeLimited HEVC supportFull HEVC hardware decoder

The most significant architectural change is the separation of I/O functions to the RP1 controller, which allows for better thermal management and performance isolation.

Conclusion

The BCM2712 SoC represents a significant advancement in the Raspberry Pi platform, bringing substantial performance improvements through its Cortex-A76 cores, enhanced graphics capabilities, and the innovative separation of I/O functions to the RP1 controller. The device tree structure provides a comprehensive view of the hardware components and their interconnections, enabling efficient driver development and system optimization.
