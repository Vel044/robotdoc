# 08 树莓派真机快照逐文件解析

10.6

快照位置：

```text
树莓派5真机文件快照/2026-05-18/
```

这份快照的用途：把当前树莓派 5 上和“新 kernel / QEMU / 设备树 / LeRobot 硬件链路”有关的小文件和查询输出固定下来，后面分析时不用反复 SSH。

重要边界：

```text
boot/bcm2712-rpi-5-b.dtb 是启动分区里的基础 dtb。
device-tree/proc-device-tree.tar 是 kernel 运行时看到的实际设备树。
两者不完全等价：firmware/bootloader/cmdline 可能会在启动阶段修改或补充设备树。
```

## 1. 快照总览

| 文件 / 目录    | 是什么                                 | 主要用途                                    |
| -------------- | -------------------------------------- | ------------------------------------------- |
| `boot/`        | 启动分区关键文件和校验信息             | 看 Pi 5 启动链、dtb、cmdline、config。      |
| `device-tree/` | 运行时 `/proc/device-tree` 摘要和打包  | 看 kernel 实际收到的设备树。                |
| `proc/`        | `/proc` 里的 kernel、cmdline、CPU 信息 | 看当前运行 kernel、构建器、架构、板卡信息。 |
| `hardware/`    | USB、V4L2、udev、设备节点查询结果      | 看摄像头和舵机串口真实枚举结果。            |

| `MANIFEST.txt` | 树莓派打包时生成的文件清单             | 确认快照包含哪些原始文件。                  |
| `README.md`    | 快照说明                               | 说明来源、内容、关键事实。                  |

## 2. `boot/config.txt`

路径：

```text
树莓派5真机文件快照/2026-05-18/boot/config.txt
```

它是什么：

```text
Raspberry Pi firmware 的配置文件。
firmware 在进入 kernel 之前读取它，用来决定启用哪些 overlay、是否自动加载 initramfs、是否 64-bit 启动等。
```

当前关键项：

| 配置                                | 当前值    | 解释                                 | 对新 kernel 的意义                                         |
| ----------------------------------- | --------- | ------------------------------------ | ---------------------------------------------------------- |
| `dtparam=audio=on`                  | 开启      | 启用音频相关配置。                   | LeRobot 当前主链路不依赖。                                 |
| `camera_auto_detect=1`              | 开启      | firmware 自动检测官方相机 overlay。  | 当前 LeRobot 用 USB UVC 摄像头，不是 MIPI 官方相机主链路。 |
| `display_auto_detect=1`             | 开启      | 自动检测 DSI 显示 overlay。          | LeRobot 主链路不依赖。                                     |
| `auto_initramfs=1`                  | 开启      | 如果存在匹配 initramfs，自动加载。   | 解释为什么启动链里有 `initramfs_2712`。                    |
| `dtoverlay=vc4-kms-v3d`             | 开启      | 启用 VC4/KMS/V3D 图形栈。            | LeRobot 无头运行时不是核心，但会影响整体图形/video 设备。  |
| `disable_fw_kms_setup=1`            | 开启      | 不让 firmware 预先塞 `video=` 参数。 | console/video 参数主要由 kernel 默认和 cmdline 决定。      |
| `arm_64bit=1`                       | 开启      | 64-bit ARM 启动。                    | 新 kernel 目标必须是 ARM64。                               |
| `disable_overscan=1`                | 开启      | 关闭 overscan 补偿。                 | 显示相关，非 LeRobot 主链路。                              |
| `arm_boost=1`                       | 开启      | 允许 firmware/板子跑更高性能档。     | 性能相关，影响真机基准。                                   |
| `[cm4] otg_mode=1`                  | 仅 CM4 段 | CM4 USB host 配置。                  | 对 Pi 5 Model B 不作为主结论。                             |
| `[cm5] dtoverlay=dwc2,dr_mode=host` | 仅 CM5 段 | CM5 DWC2 host 配置。                 | 对 Pi 5 Model B 不作为主结论。                             |

结论：

```text
Pi 5 的 LeRobot USB 链路不是靠 config.txt 里显式启用某个 USB overlay 得来的。
真实 USB host 主线来自设备树里的 RP1 DWC3 节点：rp1/usb@200000 和 rp1/usb@300000。
```

## 3. `boot/cmdline.txt` 和 `proc/cmdline.txt`

路径：

```text
boot/cmdline.txt
proc/cmdline.txt
```

`boot/cmdline.txt` 是启动分区里写给 kernel 的参数：

```text
console=serial0,115200 console=tty1 root=PARTUUID=2428fd84-02 rootfstype=ext4 fsck.repair=yes rootwait quiet splash ...
```

`proc/cmdline.txt` 是 kernel 实际运行时看到的最终参数。它包含：

```text
reboot=w
coherent_pool=1M
8250.nr_uarts=1
pci=pcie_bus_safe
cgroup_disable=memory
numa_policy=interleave
nvme.max_host_mem_size_mb=0
numa=fake=8
system_heap.max_order=0
smsc95xx.macaddr=...
vc_mem.mem_base=...
vc_mem.mem_size=...
console=ttyAMA10,115200
console=tty1
root=PARTUUID=2428fd84-02
rootfstype=ext4
rootwait
```

为什么两者不同：

```text
boot/cmdline.txt 是用户写的基础 cmdline。
proc/cmdline.txt 是 firmware / dtb chosen.bootargs / bootloader 处理后的最终 cmdline。
```

对新 kernel 的意义：

| 参数类型                             | 新 kernel 需要处理什么                                               |
| ------------------------------------ | -------------------------------------------------------------------- |
| `console=`                           | 决定早期日志输出到哪个串口/终端。Pi 5 真机最终是 `ttyAMA10,115200`。 |
| `root=` / `rootfstype=` / `rootwait` | 决定 rootfs 在哪里、怎么挂载、是否等待块设备。                       |
| `coherent_pool=1M`                   | DMA coherent 内存池相关，真硬件阶段会重要。                          |
| `pci=pcie_bus_safe`                  | PCIe 枚举策略，和 RP1/PCIe 链路有关。                                |
| `cgroup_disable=memory` / `numa=*`   | Linux 用户态环境参数，第一阶段可以先记录。                           |

结论：

```text
新 kernel 不能只读 boot/cmdline.txt 的文本假设。
真实启动时要读取 firmware 传入的最终 cmdline。
```

## 5. `boot/bcm2712-rpi-5-b.from-dtb.dts`

路径：

```text
boot/bcm2712-rpi-5-b.from-dtb.dts
```

它是什么：

```text
用 dtc 从 boot/bcm2712-rpi-5-b.dtb 反编译出来的文本版设备树。
它方便人阅读，但不是源码原始 .dts/.dtsi include 结构。
```

反编译命令：

```bash
dtc -I dtb -O dts -o bcm2712-rpi-5-b.from-dtb.dts bcm2712-rpi-5-b.dtb
```

反编译时 `dtc` 打印了不少 warning。这里先不把它当作错误，因为：

```text
文件已经成功生成。
这些 warning 多数是 unit address / simple-bus / duplicated unit-address 这类格式检查提示。
当前目标是阅读硬件描述，不是重新验证树莓派官方 dtb 的 schema。
```

这个文件里最值得先看的几段：

| 行为                            | 关键内容                                                          | 对新 kernel 的意义                                  |
| ------------------------------- | ----------------------------------------------------------------- | --------------------------------------------------- |
| root 节点                       | `compatible = "raspberrypi,5-model-b", "brcm,bcm2712"`            | 判断目标平台。                                      |
| `cpus`                          | 4 个 `arm,cortex-a76`，`enable-method = "psci"`                   | CPU 拓扑和副核启动方式。                            |
| `psci`                          | `method = "smc"`                                                  | 通过 SMC 调固件接口。                               |
| `interrupt-controller@7fff9000` | `compatible = "arm,gic-400"`                                      | 主中断控制器。                                      |
| `timer`                         | `compatible = "arm,armv8-timer"`                                  | 调度和时间源。                                      |
| `memory@0`                      | `reg = <0x00 0x00 0x28000000>`                                    | 基础 dtb 里的内存占位；实际可能被 bootloader 修正。 |
| `pcie@1000120000`               | `compatible = "brcm,bcm2712-pcie"`，`status = "okay"`             | RP1 挂在这条 PCIe 后面。                            |
| `rp1`                           | `compatible = "simple-bus"`                                       | RP1 I/O 芯片总线。                                  |
| `usb@200000` / `usb@300000`     | `compatible = "snps,dwc3"`，`dr_mode = "host"`，`status = "okay"` | Pi 5 USB host 来源。                                |
| `aliases`                       | `usb0` / `usb1` 指向 RP1 USB host                                 | 稳定命名和用户态识别。                              |

结论：

```text
这个 .dts 是学习 Pi 5 硬件结构的主要文本入口。
但如果要看 kernel 实际收到的最终设备树，要看 device-tree/proc-device-tree.tar。
```

## 6. `device-tree/proc-device-tree.tar`

路径：

```text
device-tree/proc-device-tree.tar
```

它是什么：

```text
运行中 kernel 暴露出来的 /proc/device-tree 打包。
这是 firmware/bootloader 处理后，kernel 实际看到的设备树。
```

为什么它重要：

```text
boot dtb 是启动分区文件。
proc-device-tree 是运行时事实。

如果两者不一致，新 kernel 调试时应该优先相信运行时事实。
```

配套摘要文件：

```text
device-tree/model.txt
device-tree/compatible.txt
device-tree/chosen_stdout-path.txt
device-tree/chosen_bootargs.txt
device-tree/alias_usb0.txt
device-tree/alias_usb1.txt
device-tree/alias_serial10.txt
device-tree/alias_console.txt
```

当前摘要：

```text
model: Raspberry Pi 5 Model B Rev 1.1
compatible:
  raspberrypi,5-model-b
  brcm,bcm2712
stdout-path:
  serial10:115200n8
usb0:
  /axi/pcie@1000120000/rp1/usb@200000
usb1:
  /axi/pcie@1000120000/rp1/usb@300000
serial10 / console:
  /soc@107c000000/serial@7d001000
```

对新 kernel 的意义：

```text
dtb 解析器要能解析字符串属性、reg、interrupts、phandle、aliases、chosen。
平台初始化要能从 aliases/chosen 找 console，从 pcie/rp1 找 USB host。
```

## 9. `hardware/v4l2-list-devices.txt` 和 `hardware/dev-video-ls.txt`

路径：

```text
hardware/v4l2-list-devices.txt
hardware/dev-video-ls.txt
```

它们是什么：

```text
v4l2-list-devices.txt 是 V4L2 设备分组。
dev-video-ls.txt 是 /dev/video* 字符设备节点列表。
```

当前 V4L2 设备分组：

```text
USB 2.0 Camera: USB 2.0 Camera (usb-xhci-hcd.0-1.1):
  /dev/video0
  /dev/video1
  /dev/media3

USB 2.0 Camera: USB 2.0 Camera (usb-xhci-hcd.0-1.2):
  /dev/video2
  /dev/video3
  /dev/media4

pispbe:
  /dev/video20 ... /dev/video35

rpi-hevc-dec:
  /dev/video19
```

LeRobot 命令实际用：

| LeRobot camera | OpenCV index | 真机设备节点  | 说明                                 |
| -------------- | ------------ | ------------- | ------------------------------------ |
| `handeye`      | `0`          | `/dev/video0` | 第一只 USB UVC 摄像头 capture 节点。 |
| `fixed`        | `2`          | `/dev/video2` | 第二只 USB UVC 摄像头 capture 节点。 |

注意：

```text
/dev/video1 和 /dev/video3 是同两只摄像头的附加 video 节点。
LeRobot 命令没有用它们。

/dev/video20 到 /dev/video35 是 Pi 图像处理 pispbe 节点。
当前 USB 摄像头 record 主链路不直接依赖它们。
```

对新 kernel 的意义：

```text
QEMU 第一阶段只要 mock /dev/video0 和 /dev/video2 的读帧行为即可。
真硬件阶段才需要 UVC + V4L2 + videobuf2 + media controller 完整链路。
```

## 13. `modules/lsmod.txt`

路径：

```text
modules/lsmod.txt
```

它是什么：

```text
当前运行 kernel 已加载模块列表。
```

LeRobot 硬件链路相关模块：

| 模块                | 作用                                                 |
| ------------------- | ---------------------------------------------------- |
| `uvcvideo`          | USB Video Class 摄像头驱动。                         |
| `uvc`               | UVC 辅助模块。                                       |
| `videobuf2_vmalloc` | V4L2 buffer 后端。                                   |
| `videobuf2_v4l2`    | videobuf2 和 V4L2 连接层。                           |
| `videobuf2_common`  | videobuf2 公共层。                                   |
| `videodev`          | V4L2 字符设备核心。                                  |
| `mc`                | media controller。                                   |
| `cdc_acm`           | USB CDC ACM 串口驱动。                               |
| `rp1_pio`           | RP1 PIO 相关。                                       |
| `rp1_fw`            | RP1 firmware 相关。                                  |
| `rp1_mailbox`       | RP1 mailbox。                                        |
| `pisp_be`           | Raspberry Pi 图像处理后端；不是 USB UVC 主链路核心。 |

对新 kernel 的意义：

```text
如果这些驱动做成模块，kernel release 和 /lib/modules/<uname -r> 必须匹配。
如果这些驱动内建进 kernel，则不一定需要对应 .ko，但用户态设备节点和 sysfs 行为仍要对。
```

## 14. `modules/modules.dep`、`modules.alias`、`modules.builtin`、`modules.order`

路径：

```text
modules/modules.dep
modules/modules.alias
modules/modules.builtin
modules/modules.order
```

它们是什么：

| 文件              | 作用                                                            |
| ----------------- | --------------------------------------------------------------- |
| `modules.dep`     | 模块依赖关系，`modprobe` 用它知道先加载谁。                     |
| `modules.alias`   | 设备 ID 到模块名的匹配规则，例如 USB id/class 对应哪个 driver。 |
| `modules.builtin` | 哪些模块已经编进 kernel 本体。                                  |
| `modules.order`   | 模块构建/安装顺序。                                             |

对新 kernel 的意义：

```text
Linux 用户态的自动驱动加载不是只靠 .ko 文件。
udev/modprobe 还依赖 modules.dep 和 modules.alias。
如果要复刻 Linux 模块机制，这些元数据也要匹配 kernel release。
```

QEMU 第一阶段：

```text
可以绕过真实模块自动加载，直接 mock /dev/video* 和 /dev/ttyACM*。
```

真机阶段：

```text
必须保证 UVC、CDC ACM、DWC3/xHCI、RP1 相关驱动能加载或内建。
```

## 15. `boot/boot_files_ls.txt` 和 `boot/boot_files_sha256.txt`

路径：

```text
boot/boot_files_ls.txt
boot/boot_files_sha256.txt
```

它们是什么：

```text
没有复制大文件 kernel_2712.img 和 initramfs_2712。
这两个文件只记录大小、时间、sha256。
```

当前事实：

| 文件                  | 大小             | sha256 是否记录 | 说明                         |
| --------------------- | ---------------- | --------------- | ---------------------------- |
| `kernel_2712.img`     | `28115456` bytes | 是              | 当前真机启动的 kernel 镜像。 |
| `initramfs_2712`      | `18075599` bytes | 是              | 当前真机 early userspace。   |
| `bcm2712-rpi-5-b.dtb` | `78744` bytes    | 是              | 已复制到本地。               |

对新 kernel 的意义：

```text
现在只做链路分析，不需要复制完整 kernel/initramfs。
后面如果要在 QEMU 里复刻真机 rootfs/boot 链，再决定是否复制大文件。
```

## 16. 最小阅读顺序

如果你只想搞懂“新 kernel 要先看什么”，按这个顺序看：

```text
1. boot/config.txt
2. boot/cmdline.txt + proc/cmdline.txt
3. boot/bcm2712-rpi-5-b.from-dtb.dts
4. device-tree/*.txt 摘要
5. hardware/lsusb-tree.txt
6. hardware/v4l2-list-devices.txt
7. hardware/udev-video0.txt / udev-video2.txt
8. hardware/udev-ttyACM0.txt / udev-ttyACM1.txt
9. modules/lsmod.txt
```

对应结论：

```text
启动靠 kernel image + dtb + cmdline + rootfs。
硬件认识靠设备树。
Pi 5 真硬件链路是 BCM2712 -> PCIe -> RP1 -> DWC3 -> xhci-hcd。
LeRobot 真实外设是两个 UVC 摄像头和两个 CDC ACM 串口。
QEMU 第一阶段先 mock 外设，先跑通启动和用户态。
```
