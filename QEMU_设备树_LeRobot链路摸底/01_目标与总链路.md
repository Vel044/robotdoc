# 01 目标与总链路

## 目标

不是先整理 LeRobot，也不是先整理 Python 包，而是回答：

```text
新的 kernel 如果要跑当前机器人项目，至少要支持什么？
```

当前验收负载是树莓派 5 上这条 LeRobot 任务：

```text
python -m lerobot.record
  robot:  so101_follower, /dev/ttyACM0, id=R12254705
  teleop: so101_leader,   /dev/ttyACM1, id=R07254705
  camera handeye: OpenCV index 0 -> /dev/video0, 640x360@30fps
  camera fixed:   OpenCV index 2 -> /dev/video2, 640x360@30fps
  policy: /home/vel/so101-bottle/last/pretrained_model, type=ACT
  dataset: ${HF_USER}/eval_so101_bottle
```

这条命令对新 kernel 的意义：

- 能启动 ARM64 系统。
- 能解析 Pi 5 的 dtb 和 kernel cmdline。
- 能挂载 rootfs 并运行 glibc/Python/conda 用户态。
- 能提供 `/dev/video*`、`/dev/ttyACM*`、`/proc`、`/sys` 等 Linux 设备/伪文件系统接口。
- 能支撑 OpenCV 读 UVC 摄像头、pyserial/scservo 读写 CDC ACM 串口、PyTorch CPU 推理。

## 总链路

```text
启动链：
Raspberry Pi firmware 或 QEMU
  -> kernel image
  -> dtb
  -> cmdline
  -> initramfs/rootfs
  -> 用户态 init / shell / Python

硬件链：
BCM2712
  -> PCIe pcie2
  -> RP1
  -> RP1 DWC3 USB host
  -> xhci-hcd root hub
  -> UVC camera      -> /dev/video0, /dev/video2
  -> CDC ACM serial  -> /dev/ttyACM0, /dev/ttyACM1

用户态链：
glibc / Python / conda
  -> LeRobot 0.3.4
  -> torch CPU ACT policy
  -> OpenCV camera
  -> scservo_sdk / pyserial motor bus
  -> dataset/video writer
```

核心判断：

```text
设备树描述板级硬件和总线。
USB 摄像头和舵机板不是设备树里的静态节点，而是 USB host 工作后运行时枚举出来的设备。
```
